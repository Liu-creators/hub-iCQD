## 一、 项目定位与演进分析

### 1.1 痛点与目标
传统金融 BI 终端（如 TradingView、Wind）学习门槛高、配置繁琐；而早期的单机 Function Calling 股票脚本（如 `03_本地股票助手.py`）存在**本地环境耦合重、无法多轮指代追问、原始数据撑爆上下文 Token、缺乏合规风控护栏**等问题。

本项目旨在构建一个**分布式、自然语言驱动的 ChatBI 股票分析助手**：
1. **计算与编排解耦**：Agent 编排层与数据采集层分离，通过远程 MCP 协议（SSE / Streamable HTTP）调用自建及第三方云端工具。
2. **三维极简体检**：面向非专业投资者的泛财经用户，围绕“**基础行情 + 核心估值 + 短期趋势与资讯**”输出结构化 Markdown 报告。
3. **有状态多轮分析**：支持跨轮次指代消解（如“看看苹果” $\rightarrow$ “那微软呢？” $\rightarrow$ “把这两家对比一下”）及历史会话持久化回放。
4. **金融合规刚性约束**：前置意图拦截 + 后置输出审查，严禁荐股、买卖点位指导与目标价预测。

## 三、 核心业务流程与 LangGraph 状态机设计

### 3.1 全局状态（`StockAgentState`）数据结构设计

为兼顾多轮指代能力与 Token 成本控制，LangGraph 的 `State` 采用如下结构设计：

```python
from typing import Annotated, Literal, Optional, TypedDict
from langgraph.graph.message import add_messages
from langchain_core.messages import AnyMessage

class StockSnapshot(TypedDict):
    ticker: str                        # 股票代码，如 "AAPL"
    company_name: str                  # 公司名称，如 "Apple Inc."
    currency: str                      # 币种，如 "USD"
    price_info: dict                   # 最新价、今日涨跌幅、成交量、52周高低点
    fundamentals: dict                 # 市值、PE(TTM)、PB、股息率、营收同比增速
    trend_info: dict                   # 近1月涨跌幅、20日均线值、均线强弱状态
    latest_news: list[dict]            # 最新3条新闻 [{"title": ..., "publisher": ..., "published_at": ...}]
    fetch_status: Literal["ok", "partial", "error"]
    error_msg: Optional[str]

class StockAgentState(TypedDict):
    # 1. 聊天历史（由 Checkpointer 持久化）
    messages: Annotated[list[AnyMessage], add_messages]
    
    # 2. 会话级上下文槽位（跨轮次保留，用于指代消解）
    current_tickers: list[str]         # 当前正在讨论的股票代码列表，如 ["AAPL", "MSFT"]
    
    # 3. 单轮执行流转槽位（每轮覆盖，防止撑爆上下文）
    intent: Literal["stock_query", "general_qa", "compliance_reject"]
    analysis_mode: Literal["single", "compare", "none"]
    reject_reason: Optional[str]       # 触发前置合规拦截时的原因说明
    stock_data_context: dict[str, StockSnapshot]  # 当前轮次 MCP 返回的精简数据包
    draft_report: Optional[str]        # 分析师节点生成的初稿
    compliance_passed: bool            # 后置审查是否通过
```

### 3.2 四节点职责与流转逻辑

#### 节点 1：意图路由与合规守卫 (`router_and_guard_node`)
* **输入**：`messages`（最近 $N$ 轮对话）、`current_tickers`（上一轮讨论的标的）。
* **核心处理逻辑**：
  1. **合规预检**：判断用户是否要求明确买卖指令（如“帮我推荐三只明天必涨的股票”、“特斯拉现在能抄底吗”、“预测下周苹果能涨到多少”）。若命中，设置 `intent = "compliance_reject"`，并记录 `reject_reason`。
  2. **实体提取与指代消解**：
     * 显式提及新标的（如“查一下英伟达”）$\rightarrow$ 映射为标准美股代码 `["NVDA"]`。
     * 对比追问（如上一轮是 `["AAPL"]`，本轮问“和微软比呢？”）$\rightarrow$ 合并为 `["AAPL", "MSFT"]`，设置 `analysis_mode = "compare"`。
     * 延续追问（如“它的市盈率高吗？”）$\rightarrow$ 继承上一轮 `current_tickers = ["AAPL"]`，设置 `analysis_mode = "single"`。
  3. **常规概念/闲聊识别**：若用户询问“什么是市盈率 PE？”或日常打招呼，设置 `intent = "general_qa"`。
* **条件路由 (`route_after_guard`)**：
  * `intent == "compliance_reject"` $\rightarrow$ 跳转至 `compliance_output_node`（输出温和拒答话术 + 引导用户改为查询客观基本面）。
  * `intent == "general_qa"` $\rightarrow$ 跳转至 `compliance_output_node`（直接回答财经概念并附免责声明）。
  * `intent == "stock_query"` $\rightarrow$ 跳转至 `data_fetcher_node`。

#### 节点 2：数据采集专员 (`data_fetcher_node`)
* **输入**：`current_tickers`。
* **核心处理逻辑**：
  1. 通过远程 MCP Client（SSE / Streamable HTTP）并发调用云端 MCP Server 工具：
     * 调用自建 MCP：`get_stock_3d_checkup(tickers=current_tickers)` 获取行情、估值、均线趋势摘要。
     * 调用资讯 MCP：`get_stock_latest_news(ticker=t, limit=3)` 获取最新 3 条相关新闻。
  2. **容错与降级处理**：
     * 若某只股票代码无效（如 `yfinance` 返回空数据），将该 Ticker 标记为 `fetch_status = "error"`，记录提示信息（如“未找到代码为 XXX 的美股数据”）。
     * 若某项财务指标缺失（如亏损企业无正向 PE，或科技成长股无股息率），统一标准化为 `"N/A (亏损或未披露)"` 或 `"0.00% (无分红)"`，严禁传递空字符串让大模型瞎猜。
  3. 将组装好的结构化精简字典写入 `stock_data_context`。

#### 节点 3：金融分析师 (`analyst_node`)
* **输入**：用户问题、`analysis_mode`、`stock_data_context`。
* **核心处理逻辑**：
  1. **强数据绑定约束**：System Prompt 明确规定“**仅允许使用 `stock_data_context` 中提供的数值，严禁使用训练预训练知识编造股价或财报数据；若字段为 N/A，必须如实说明**”。
  2. **按模式生成结构化初稿 (`draft_report`)**：
     * **单股模式 (`single`)**：输出“三维体检卡片表” + 估值诊断 + 短期趋势与消息面联动分析 + 客观利弊总结（亮点 vs 风险点）。
     * **对比模式 (`compare`)**：输出“多股横向指标对比表” + 体量/估值/成长性/短期强弱四维对比结论。

#### 节点 4：合规审查与格式化输出 (`compliance_output_node`)
* **输入**：`intent`、`draft_report`、`reject_reason`。
* **核心处理逻辑**：
  1. **违规词扫描与脱敏**：检查 `draft_report` 是否意外包含违规投资建议词库（如：`["强烈推荐", "建议买入", "建议卖出", "目标价", "抄底", "止盈", "止损", "满仓", "加仓"]`）。若命中，自动将其改写为客观描述（如将“建议买入”替换为“基本面指标表现较强”）。
  2. **免责声明注入**：在回复末尾强制追加统一格式的合规尾部：
     > ⚠️ **合规与风险提示**：本报告数据来源于公开市场（Yahoo Finance 等），由 AI 自动汇总生成，仅供客观数据参考与学习交流，**不构成任何投资建议、买卖依据或目标价预测**。股市有风险，投资需谨慎。
  3. 将最终合规消息追加至 `messages`，由 Checkpointer 自动持久化落盘。

## 四、 云端 MCP 服务接口契约设计（Interface Spec）

### 4.1 自建封装云端 MCP Server (`stock-core-mcp`)

采用 `FastMCP` 构建，通过 `transport="sse"` 或 `streamable-http` 部署在云端容器，对外暴露高内聚工具，**将原始时序计算下沉在 MCP 服务端完成**，绝不向 Agent 传输原始 K 线明细表。

#### 工具 1：`get_stock_3d_summary`（获取股票三维体检核心摘要）
* **功能描述**：一次性获取指定美股代码的基础行情、5 项核心基本面估值指标、以及近 1 个月趋势与 20 日均线状态。
* **入参 Schema**：
  ```json
  {
    "type": "object",
    "properties": {
      "tickers": {
        "type": "array",
        "items": { "type": "string" },
        "description": "标准美股股票代码列表，全部大写，例如 [\"AAPL\", \"NVDA\"]，单次最多支持 5 只股票"
      }
    },
    "required": ["tickers"]
  }
  ```
* **服务端内部计算逻辑（基于 `yfinance`）**：
  1. 拉取 `yf.Ticker(ticker).history(period="2mo")` 与 `yf.Ticker(ticker).info`。
  2. **基础行情**：提取最新收盘价 `latest_price`、前一日收盘价计算 `daily_change_pct`、最新成交量 `volume`、52 周最高价 `high_52w` 与最低价 `low_52w`、以及当前价格所处 52 周分位值。
  3. **核心基本面（5 项）**：
     * `market_cap_fmt`：市值格式化（自动转换为 `$X.XX T` 万亿或 `$X.XX B` 十亿）。
     * `pe_ttm`：`trailingPE`（滚动市盈率，保留 2 位小数）。
     * `pb_ratio`：`priceToBook`（市净率，保留 2 位小数）。
     * `dividend_yield_pct`：`dividendYield` 转换为百分比字符串。
     * `revenue_growth_yoy_pct`：`revenueGrowth` 同比营收增速百分比。
  4. **极简趋势指标**：
     * `return_1m_pct`：近 21 个交易日累计涨跌幅百分比。
     * `sma_20`：近 20 个交易日收盘价算术均值。
     * `trend_signal`：若 `latest_price >= sma_20` 返回 `"高于20日均线 (短期偏强)"`，否则返回 `"低于20日均线 (短期偏弱)"`。
* **出参 JSON 示例（高浓度摘要，单股仅约 20 行）**：
  ```json
  {
    "AAPL": {
      "ticker": "AAPL",
      "company_name": "Apple Inc.",
      "currency": "USD",
      "fetch_status": "ok",
      "as_of_date": "2026-10-23",
      "price_info": {
        "latest_price": 235.40,
        "daily_change_pct": "+1.25%",
        "volume": "42.15M",
        "high_52w": 248.00,
        "low_52w": 182.50
      },
      "fundamentals": {
        "market_cap": "$3.58T",
        "pe_ttm": 34.20,
        "pb_ratio": 52.10,
        "dividend_yield": "0.44%",
        "revenue_growth_yoy": "+6.10%"
      },
      "trend_info": {
        "return_1m_pct": "+4.80%",
        "sma_20": 229.85,
        "price_vs_sma20_pct": "+2.41%",
        "trend_signal": "高于20日均线 (短期偏强)"
      }
    }
  }
  ```

### 4.2 资讯类云端 MCP 工具 (`get_stock_news`)
* **功能描述**：获取目标股票最新 3 条市场新闻摘要，用于辅助解释近期股价波动原因。
* **支持双模式接入**：
  * **主模式**：优先接入第三方公开云端财经/搜索 MCP Server（通过 `servers_config.json` 配置 URL）。
  * **兜底模式**：由自建 MCP Server 封装 `yf.Ticker(ticker).news[:3]`，提取 `title`、`publisher`、`publish_time`。

### 4.3 鉴权与租户限流预留设计 (`auth_middleware`)
* **客户端侧（MCP Client）**：在建立 SSE / Streamable HTTP 连接时，统一通过 `get_mcp_headers()` 函数构造请求头：
  ```python
  def get_mcp_headers() -> dict[str, str]:
      # TODO: 后续接入租户级 Bearer Token / API Key 鉴权与请求签名
      api_key = os.getenv("MCP_CLOUD_API_KEY", "dev-placeholder-token")
      return {"Authorization": f"Bearer {api_key}", "X-Tenant-ID": "default"}
  ```
* **服务端侧（FastMCP Server）**：预留 `auth_middleware` 钩子，MVP 阶段默认放行并记录访问日志，V2.0 无需改动业务 Tool 代码即可开启鉴权与限流。

## 六、 多轮对话与历史会话管理设计

### 6.1 会话持久化机制（Checkpointer）
* **开发/单机验证环境**：使用 `langgraph.checkpoint.sqlite.aio.AsyncSqliteSaver`（持久化到本地 `chatbi_sessions.db`），零外部依赖即可支持跨进程重启后的历史会话恢复。
* **云端生产环境**：通过环境变量 `CHECKPOINT_DB_URI` 一键切换为 `AsyncPostgresSaver`，实现分布式无状态 Agent 节点的会话共享。

### 6.2 会话管理功能设计
1. **新建会话**：生成唯一 `thread_id`（格式：`session_<timestamp>_<short_uuid>`），清空当前视图并初始化欢迎引导语。
2. **会话列表读取**：维护轻量会话元数据表（`thread_id`、`title` 首问自动摘要、`updated_at`、`last_tickers`），在侧边栏展示历史对话列表。
3. **上下文防膨胀策略**：
   * `stock_data_context` 仅存储当前轮次 MCP 返回的精简 JSON，不随 `messages` 无限累积。
   * 向 LLM 传入 `messages` 时，保留最近 `MAX_HISTORY_TURNS = 6` 轮完整对话 + `current_tickers` 状态槽位，兼顾多轮指代准确性与低推理延迟。

## 七、 异常处理与边界降级设计

| 异常场景 | 触发条件 | 系统降级与用户反馈策略 |
| :--- | :--- | :--- |
| **1. 股票代码无法识别或退市** | 用户输入未上市企业、A股代码（MVP阶段未开）或拼写错误，导致 `yfinance` 返回空数据 | 不抛未捕获异常；由 `Analyst Node` 礼貌提示：“暂未检索到对应美股代码的数据，当前 MVP 版本主要支持美股市场（如 AAPL、NVDA、TSLA），请确认股票名称或代码。” |
| **2. 云端 MCP 服务超时/断连** | 网络抖动或远程 SSE 服务不可达 | MCP Client 内置指数退避重试（`max_retries=2, timeout=8s`）；若仍失败，向用户返回友好提示：“云端行情服务暂时繁忙，请稍后重试”，不生成虚假数据。 |
| **3. 第三方资讯 MCP 不可用** | 外部公开新闻 MCP 限流或挂掉 | 自动降级为仅使用自建 `yfinance.news` 或在报告中标注“暂无最新关联新闻”，核心行情与估值体检正常生成。 |
| **4. 单次对比股票数量过多** | 用户一次要求对比超过 5 只股票（如“把纳斯达克前20大公司都对比一下”） | 在 `Router & Guard Node` 截断前 5 只核心标的，并在回复开头提示：“为保证对比表格清晰可读，本次为您选取前 5 只代表性股票进行横向对比。” |
