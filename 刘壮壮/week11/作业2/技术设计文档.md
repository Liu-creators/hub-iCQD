## 一、 系统技术架构分层划分

为满足“**Agent 轻量化、MCP 云端分布式部署、多轮会话可持久化**”的核心目标，系统从上至下划分为 **5 个技术分层**、物理上拆分为 **2 个独立部署单元（应用端 `agent_app` 与云端服务 `mcp_server`）**。

## 三、 云端 MCP 服务层详细技术设计 (`mcp_server`)

### 3.1 股票三维指标计算与清洗规范 (`calculator.py`)

为彻底解决“原始 K 线数据撑爆大模型上下文”的问题，所有计算在 `mcp_server/calculator.py` 内通过 `pandas` 完成，只输出高浓度标量结果：

1. **大数单位格式化算法 (`format_large_number`)**：
   * $\ge 10^{12}$：转换为 `f"${val / 1e12:.2f}T"`（万亿美元）
   * $\ge 10^{9}$：转换为 `f"${val / 1e9:.2f}B"`（十亿美元）
   * $\ge 10^{6}$：转换为 `f"${val / 1e6:.2f}M"`（百万美元）
   * 缺失或 `None`：返回 `"N/A"`
2. **核心指标计算公式**：
   * **今日涨跌幅 (`daily_change_pct`)**：取 `history(period="3mo")['Close']` 最后两行 $P_t, P_{t-1}$：
     $$\text{Daily Change (\%)} = \frac{P_t - P_{t-1}}{P_{t-1}} \times 100\%$$
   * **近 1 个月涨跌幅 (`return_1m_pct`)**：取最近 21 个交易日收盘价 $P_t$ 与 $P_{t-21}$（若不足 21 日则取首行）：
     $$\text{Return}_{1\text{M}} (\%) = \frac{P_t - P_{t-21}}{P_{t-21}} \times 100\%$$
   * **20 日简单移动平均线 (`sma_20`) 与强弱判定**：
     $$\text{SMA}_{20} = \frac{1}{20}\sum_{i=0}^{19} P_{t-i}, \quad \text{偏离度} = \frac{P_t - \text{SMA}_{20}}{\text{SMA}_{20}} \times 100\%$$
     * 当 $P_t \ge \text{SMA}_{20}$ 时，标记为 `"高于20日均线 (短期偏强)"`；否则为 `"低于20日均线 (短期偏弱)"`。
3. **基本面字段提取映射表（源自 `yf.Ticker(ticker).info`）**：
   * `marketCap` $\rightarrow$ `fundamentals.market_cap`
   * `trailingPE` $\rightarrow$ `fundamentals.pe_ttm`（若为空或负值，标注 `"N/A (亏损或暂未披露)"`）
   * `priceToBook` $\rightarrow$ `fundamentals.pb_ratio`
   * `dividendYield` $\rightarrow$ `fundamentals.dividend_yield`（注意：`yfinance` 新版部分返回百分比数值或小数，需统一归一化为百分比字符串，无分红返回 `"0.00% (无分红)"`）
   * `revenueGrowth` $\rightarrow$ `fundamentals.revenue_growth_yoy`（乘以 100 格式化为带正负号百分比）

## 四、 LangGraph 智能编排层详细技术设计 (`agent_app/graph`)

### 4.1 节点 1：意图路由与指代消解 (`router_and_guard_node`)

为了避免用正则表达式硬编码解析用户意图，该节点使用 LLM 的 **结构化输出（Structured Output / JSON Schema）** 一次性完成**合规预检 + 意图分类 + 股票名称转 Ticker + 多轮指代消解**。

#### 结构化输出 Schema 定义 (`RouterDecision`)
```python
from pydantic import BaseModel, Field
from typing import Literal, Optional

class RouterDecision(BaseModel):
    intent: Literal["stock_query", "general_qa", "compliance_reject"] = Field(
        description="用户意图分类：stock_query(股票查询/对比/追问), general_qa(财经概念解释或日常闲聊), compliance_reject(违规求荐股/求买卖点位/预测目标价)"
    )
    resolved_tickers: list[str] = Field(
        default_factory=list,
        description="结合历史 current_tickers 消解后的标准美股代码列表（大写，如 ['AAPL', 'MSFT']，最多5个）"
    )
    analysis_mode: Literal["single", "compare", "none"] = Field(
        default="none",
        description="single(单只股票分析), compare(2只及以上股票横向对比), none(非股票数据查询)"
    )
    reject_or_direct_reply: Optional[str] = Field(
        default=None,
        description="当 intent 为 compliance_reject 时填写温和拒答话术；当 intent 为 general_qa 时直接生成概念解释回复"
    )
```

#### 多轮指代消解规则（内置于 `ROUTER_PROMPT`）
* **规则 1（新增替换）**：上一轮 `current_tickers=["AAPL"]`，本轮用户问“那微软呢？”或“看看特斯拉” $\rightarrow$ `resolved_tickers=["MSFT"]`（或 `["TSLA"]`），`analysis_mode="single"`。
* **规则 2（追加对比）**：上一轮 `current_tickers=["AAPL"]`，本轮用户问“把它和微软对比一下”或“和英伟达比谁估值低？” $\rightarrow$ `resolved_tickers=["AAPL", "MSFT"]`，`analysis_mode="compare"`。
* **规则 3（属性追问）**：上一轮 `current_tickers=["AAPL"]`，本轮用户问“它的市盈率和分红怎么样？” $\rightarrow$ 保持 `resolved_tickers=["AAPL"]`，`analysis_mode="single"`。
* **规则 4（中英文名自动映射）**：用户输入中文名（如“苹果”、“微软”、“英伟达”、“谷歌”、“特斯拉”、“亚马逊”、“台积电”、“拼多多”）自动映射为标准美股 Ticker（`AAPL`, `MSFT`, `NVDA`, `GOOGL`, `TSLA`, `AMZN`, `TSM`, `PDD`）。

### 4.2 节点 2：远程 MCP 数据采集 (`data_fetcher_node`)

* **职责**：根据 `state["current_tickers"]` 调用 `RemoteMCPClientManager`。
* **执行流程**：
  1. 调用远程 `get_stock_3d_summary(tickers=state["current_tickers"])`。
  2. 针对 `fetch_status == "ok"` 的股票，并发调用远程 `get_stock_latest_news(ticker=t, limit=3)`（若配置了第三方公开新闻 MCP 则优先路由至第三方 Server，否则路由至自建 Server）。
  3. 将新闻列表合并至对应股票的 `latest_news` 字段，写入 `state["stock_data_context"]`。

### 4.3 节点 3：多维金融分析师 (`analyst_node`)

* **职责**：根据 `state["analysis_mode"]`（`"single"` 或 `"compare"`）选择对应的 Prompt 模板，将 `state["stock_data_context"]` 序列化为 JSON 注入上下文，生成 `draft_report`。
* **防幻觉技术手段**：
  * `temperature = 0.1`（低温采样，确保数值引用严谨）。
  * Prompt 中包含 `stock_data_context` 原文 JSON，并强制要求表格中的每一项数字必须与 JSON 严格一致。

### 4.4 节点 4：后置合规审查与格式化 (`compliance_output_node`)

* **职责**：作为图的唯一出口节点（汇聚所有分支），负责最终安全把关与消息归档。
* **雙重处理机制**：
  1. **违规词正则替换词典 (`FORBIDDEN_PATTERNS`)**：
     ```python
     FORBIDDEN_REPLACEMENTS = {
         r"强烈推荐(买入|建仓)?": "基本面指标备受关注",
         r"建议(立即)?(买入|抄底|加仓|满仓)": "可关注其客观估值与增长表现",
         r"建议(立即)?(卖出|清仓|割肉|止损)": "需留意其潜在波动风险",
         r"目标价(位)?(看高至|预计达到)?": "历史参考价格区间",
     }
     ```
  2. **幂等追加免责声明**：检查文本尾部是否已含免责声明标识，若无则统一拼接 `DISCLAIMER_FOOTER`，最后封装为 `AIMessage(content=final_text)` 返回以追加进 `state["messages"]`。

### 4.5 状态图拓扑构建 (`workflow.py`)

```python
from langgraph.graph import StateGraph, START, END
from agent_app.graph.state import StockAgentState
from agent_app.graph.nodes import (
    router_and_guard_node,
    data_fetcher_node,
    analyst_node,
    compliance_output_node,
)

def route_after_guard(state: StockAgentState) -> str:
    if state.get("intent") == "stock_query":
        return "data_fetcher"
    # compliance_reject 和 general_qa 直接走合规输出节点包装后结束
    return "compliance_output"

def build_stock_graph(checkpointer=None):
    builder = StateGraph(StockAgentState)
    
    builder.add_node("router_and_guard", router_and_guard_node)
    builder.add_node("data_fetcher", data_fetcher_node)
    builder.add_node("analyst", analyst_node)
    builder.add_node("compliance_output", compliance_output_node)
    
    builder.add_edge(START, "router_and_guard")
    builder.add_conditional_edges(
        "router_and_guard",
        route_after_guard,
        {
            "data_fetcher": "data_fetcher",
            "compliance_output": "compliance_output",
        },
    )
    builder.add_edge("data_fetcher", "analyst")
    builder.add_edge("analyst", "compliance_output")
    builder.add_edge("compliance_output", END)
    
    return builder.compile(checkpointer=checkpointer)
```

## 五、 远程 MCP 通信层技术设计 (`agent_app/mcp_client`)

### 5.1 多云端 MCP Server 配置文件规范 (`servers_config.json`)

支持同时挂载**自建云端 MCP** 与 **第三方公开云端 MCP**，通过统一协议字段声明：

```json
{
  "mcpServers": {
    "stock_core_cloud": {
      "transport": "sse",
      "url": "http://localhost:8900/sse",
      "timeout_seconds": 10,
      "retries": 2,
      "auth_env_key": "MCP_STOCK_CORE_API_KEY",
      "enabled": true,
      "description": "自建云端美股三维体检与资讯 MCP 服务"
    },
    "public_finance_news_cloud": {
      "transport": "sse",
      "url": "https://example-public-mcp.cloud/finance/sse",
      "timeout_seconds": 8,
      "retries": 1,
      "auth_env_key": "MCP_PUBLIC_NEWS_API_KEY",
      "enabled": false,
      "description": "第三方公开云端财经新闻 MCP 服务（可选开启）"
    }
  }
}
```

### 5.2 远程客户端连接与调用流程 (`RemoteMCPClientManager`)

基于官方 `mcp.client.sse.sse_client` 与 `mcp.ClientSession` 实现：
1. **按需短连接 / 会话池复用**：在 `data_fetcher_node` 执行工具调用时，通过 `async with sse_client(url=server_url, headers=auth_headers) as (read, write):` 建立异步通道并完成 `session.initialize()`。
2. **返回结果反序列化**：解析 MCP 标准返回对象 `CallToolResult.content` 中的 `TextContent.text`，自动通过 `json.loads` 还原为 Python 字典供下游节点消费。
3. **异常捕获与重试**：对 `httpx.ConnectError`、`TimeoutError` 进行最多 `retries` 次指数退避重试（间隔 $1\text{s}, 2\text{s}$）；全部失败时返回标准降级结构体 `{"fetch_status": "error", "error_msg": "远程 MCP 服务连接失败"}`，保证 LangGraph 状态机不崩溃。

## 六、 存储层与会话持久化技术设计 (`agent_app/storage`)

系统使用同一个 SQLite 数据库文件（开发环境 `chatbi_state.db`）或 PostgreSQL 实例（生产环境）承载两类数据：

### 6.1 LangGraph 原生状态表（由 `SqliteSaver` 自动创建维护）
* `checkpoints` 表：按 `(thread_id, checkpoint_ns, checkpoint_id)` 存储每一步图执行后的 `StockAgentState` 快照（含 `messages` 与 `current_tickers`）。
* `writes` 表：存储节点执行过程中的增量写入记录。

### 6.2 业务侧会话列表元数据表 (`chat_sessions`)
由于 LangGraph Checkpointer 仅负责按已知 `thread_id` 读写状态，前端侧边栏需要展示“历史会话列表（含会话标题、最后更新时间、关联股票）”，因此由 `SessionMetadataStore` 维护一张轻量业务表：

```sql
CREATE TABLE IF NOT EXISTS chat_sessions (
    thread_id TEXT PRIMARY KEY,          -- 会话唯一ID，如 "thread_20261023_a1b2c3"
    title TEXT NOT NULL,                 -- 会话标题（取用户首句提问前18个字符）
    active_tickers TEXT DEFAULT '[]',    -- JSON数组字符串，记录当前会话讨论的股票代码
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.3 历史消息裁剪算法（防止长对话 Token 溢出）
在 `router_and_guard_node` 和 `analyst_node` 调用 LLM 前，执行滑动窗口裁剪函数 `trim_conversation_history(messages, max_turns=6)`：
* 仅提取最近 $6$ 轮（最多 $12$ 条 `HumanMessage` / `AIMessage`）传给 LLM。
* 完整的历史消息依然保存在 Checkpointer 数据库中，供前端 UI 完整回放。

## 八、 开发实施阶段划分（Implementation Roadmap）

为确保代码高内聚、可独立测试，建议按以下 **4 个阶段（Phases）** 推进编码实现：

### Phase 1：云端 MCP 服务端开发与独立验证 (`mcp_server/`)
* **任务 1.1**：编写 `mcp_server/calculator.py`，实现基于 `yfinance` 的单股三维指标计算与新闻提取，处理停牌、亏损、无分红等边界情况。
* **任务 1.2**：编写 `mcp_server/auth.py` 与 `mcp_server/server.py`，使用 `FastMCP` 封装 `get_stock_3d_summary` 与 `get_stock_latest_news` 两个工具，支持 SSE 启动。
* **阶段产物验证**：启动 `python -m mcp_server.server`，可通过测试脚本远程调用并返回标准 JSON。

### Phase 2：远程 MCP 客户端与持久化存储层实现 (`agent_app/mcp_client` & `storage`)
* **任务 2.1**：编写 `servers_config.json` 与 `RemoteMCPClientManager`，实现异步 SSE 调用、超时重试及预留鉴权 Header。
* **任务 2.2**：编写 `SessionMetadataStore`，实现 `chat_sessions` SQLite 表创建与会话 CRUD 接口。

### Phase 3：LangGraph 四节点状态机编排实现 (`agent_app/graph/`)
* **任务 3.1**：编写 `state.py` 与 `prompts.py`，定义 `StockAgentState`、`RouterDecision` 及单股/多股 Markdown 提示词模板。
* **任务 3.2**：编写 `nodes.py` 与 `workflow.py`，串联 4 个节点与 `SqliteSaver` Checkpointer。
* **阶段产物验证**：通过命令行脚本测试“查苹果” $\rightarrow$ “那微软呢？” $\rightarrow$ “对比这两家” $\rightarrow$ “明天能满仓买吗？”四轮连续对话。

### Phase 4：Streamlit 交互前端与多轮会话联调 (`agent_app/app.py`)
* **任务 4.1**：开发 Streamlit 侧边栏（新建对话、历史会话切换、当前关注标的标签展示）与主聊天区。
* **任务 4.2**：接入 LangGraph 节点执行状态实时展示（如“正在进行合规与意图分析...” $\rightarrow$ “正在调用云端 MCP 采集 AAPL, MSFT 数据...” $\rightarrow$ “正在生成三维分析报告...”）。
