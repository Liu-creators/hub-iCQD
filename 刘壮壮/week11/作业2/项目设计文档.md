## 一、 核心业务与金融指标基线（替你拍板的最简方案）

既然你对股票业务不熟，我们千万不要一上来就搞复杂的“技术面 K 线形态（如 MACD、布林带）”或复杂的财报精算，而是采用**普通人也能一眼看懂的“三维体检法”**，底层数据源直接选用最省心的 **美股 + `yfinance`（Yahoo Finance 开源库）**（无需注册账号、无需申请 Token、免费、全球网络访问稳定、数据结构极其标准，后期随时可无缝扩展 A 股 `AkShare`）。

| 功能模块 | 具体包含内容（MVP 最简集） | 为什么选它（业务解释） |
| --- | --- | --- |
| **1. 基础行情查询** | 最新股价、今日涨跌幅、成交量、52周最高/最低价 | 回答“这只股票现在多少钱、最近是在高点还是低点” |
| **2. 核心基本面（估值）** | **市值 (Market Cap)**、**市盈率 (PE)**、**市净率 (PB)**、**股息率 (Dividend Yield)**、**营收增速** | 只需这 5 个指标，就能让大模型判断这家公司“体量多大、当前贵不贵、分不分红、还在不在增长” |
| **3. 极简趋势与资讯** | 近 1 个月涨跌百分比、20日均线对比（高于均线=短期偏强）、最新 3 条相关新闻标题 | 结合近期走势和消息面，回答“为什么最近涨/跌了” |
| **4. 合规风控红线** | **强约束：绝不提供买卖建议与目标价预测** | 仅做客观数据汇总与多维利弊对比（如“估值偏高但增速快”），每次输出强制附带免责声明 |

## 二、 LangGraph 多 Agent 协同架构设计

为了解决传统 BI 操作复杂的问题，同时避免单个 Agent 职责过重导致 Prompt 混乱，我们在 LangGraph 中设计一个经典的 **4 节点状态图（StateGraph）**。

```
[用户输入] 
   │
   ▼
[1. 意图路由与合规守卫 (Router & Guard Node)] 
   ├── (触发违规/求荐股) ──────────────────► [直接拦截并温和拒答]
   ├── (日常闲聊/概念解释) ─────────────────► [直接生成回复]
   └── (股票查询与分析需求)
         │
         ▼
[2. 数据采集专员 (Data Fetcher Agent)] ◄───► 调用 MCP Servers (云端公开 / 云端自建)
         │ (将结构化精简数据写入 Graph State)
         ▼
[3. 金融分析师 (Analyst Agent)] ───────────► 基于客观数据生成 Markdown 表格与多维解读
         │
         ▼
[4. 合规审查与格式化输出 (Compliance Output)] ► 检查是否含违规词 + 注入免责声明 + 写入历史记录

```

### 核心状态（Graph State）设计

为了支持丝滑的多轮对话（例如用户先问“看看苹果”，下一句问“那微软呢？”），LangGraph 的 `State` 不仅存聊天记录，还会显式维护两个核心槽位：

* `messages`: 历史对话消息列表。
* `current_tickers`: 当前正在讨论的股票代码列表（如 `["AAPL"]`），方便多轮对话自动指代消解。
* `stock_data_context`: 当前轮次从 MCP 获取到的精简 JSON 数据（阅后即焚或仅保留摘要，防止撑爆多轮对话 Token）。

## 三、 云端 MCP 混合架构与预留设计

你提到“不想在本地部署 Agent，且 MCP 包含第三方公开云端 + 自建封装云端”，在工程上我们将全部采用 **远程 HTTP/SSE (Server-Sent Events) 或 Streamable HTTP 协议** 进行解耦通信：

1. **自建封装云端 MCP Server（主力）：**
* 使用官方 Python SDK (`FastMCP`) 编写一个轻量级服务，底层调用 `yfinance`。
* **核心细节：** 绝不把原始的几百行历史数据直接返回给 Agent！在 MCP Tool 内部直接用代码算好“近1月涨跌幅”、“20日均线均值”，只向 Agent 返回不到 20 行的**高浓度统计摘要 JSON**。


2. **第三方公开云端 MCP Server（辅助）：**
* 直接通过配置文件接入现成的云端搜索或财经资讯 MCP（例如获取最新市场新闻摘要）。


3. **鉴权预留（TODO 占位）：**
* 在 MCP Client 连接层和服务端中间件统一预留 `auth_middleware` 钩子函数，目前直接放行，代码中标记 `# TODO: 后续接入 Bearer Token / API Key 鉴权与租户限流`。

## 四、 交互呈现与多轮对话持久化（最简落地）

* **数据呈现方式（纯 Markdown 结构体）：**
* 不引入复杂的前端图表库。统一要求 `Analyst Agent` 输出 **“结构化 Markdown 指标对比表 + 核心结论要点列表”**。任何支持 Markdown 的前端聊天框（如 Streamlit、Chainlit、Next.js 聊天模板）都能直接完美渲染。


* **多轮对话与历史记录：**
* 直接利用 **LangGraph 原生的 Checkpointer 机制**。
* 开发测试阶段使用 `MemorySaver` 或轻量的 `SqliteSaver`（单文件数据库，零配置）；云端部署时只需改一行代码切换为 `PostgresSaver`，即可天然实现按 `thread_id`（会话 ID）隔离的多轮上下文记忆与历史对话回放。

## 五、 最终确认的需求边界清单（Scope）

* **包含（In-Scope）：**
* 支持自然语言单只股票查询、两只或多只股票横向对比（如：“对比一下英伟达和苹果的估值”）。
* 支持基于 `thread_id` 的多轮追问与历史会话列表读取。
* 基于 LangGraph 的多节点协同编排（路由、采集、分析、合规）。
* 通过远程协议（SSE/HTTP）调用云端 MCP 服务，代码内预留鉴权 `# TODO`。
* 严格的“不荐股”Prompt 护栏与尾部免责声明。


* **暂不包含（Out-of-Scope，留待 V2.0）：**
* 前端动态 K 线图/ECharts 图表渲染。
* 实时毫秒级高频行情推送、真实账户交易对接。
* 复杂的用户注册登录与多租户计费系统。
