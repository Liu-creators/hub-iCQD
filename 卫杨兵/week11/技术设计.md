以下为 **ChatBI 技术设计方案 V0.1**，对应已确认的一期 MVP 边界。方案按“可落地、单租户、内部 PC Web、MySQL 只读、允许脱敏后调用公有云大模型”设计。

---

# 1. 设计原则与硬约束

1. **用户不接触 SQL**：SQL 仅在服务端生成、校验、执行；前端和普通用户不可见。
2. **自动优先**：自动追问、自动选图、自动异常检测、自动归因、自动生成 3–5 条解读。
3. **安全底线**：MySQL 只读账号、禁止 DDL/DML、防注入、30 秒超时、返回行数上限 1000。
4. **失败兜底**：SQL 执行失败或空结果，自动重试修正 1 次；仍失败给可理解提示，不暴露 SQL。
5. **不编造**：解读只基于图表内数据并引用数值；推测必须标注；无法归因明确提示。
6. **一期边界**：不做分享、输入联想、猜你想问、表格/明细/导出、移动端；只预留接口和交互位置。
7. **准确率目标**：100 条标注问题离线评测，单问级 SQL 准确率 ≥90%。

# 2. 总体架构

```text
PC Web (React + TS + ECharts)
        │ HTTPS / SSE
        ▼
Nginx / API Gateway
        │
        ▼
FastAPI 应用服务
 ├─ Auth & Session
 ├─ Conversation Orchestrator（多轮/追问/新话题）
 ├─ NL2SQL Service（LLM + 语义检索 + SQL 校验 + 重试）
 ├─ Query Executor（只读 MySQL 连接池）
 ├─ Chart Service（自动选型 + 图表数据整形）
 ├─ Insight Service（异常检测 + 归因 + 数据解读）
 ├─ Share/联想预留 API
 └─ Admin Service（数据源/语义/阈值/审计）
        │
        ├─ PostgreSQL：会话、消息、语义元数据、审计、评测集
        ├─ Redis（可选）：会话缓存、限流、任务状态
        ├─ MySQL 只读数据源
        └─ LLM Gateway → 公有云大模型（脱敏后调用）
```

建议单体模块化部署，Docker Compose 单机即可；后续可拆服务。

# 3. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React + TypeScript + Ant Design + ECharts | PC Web；ECharts 支持折线/柱状/堆叠柱/饼图 |
| 后端 | Python + FastAPI | 适合 LLM 编排、流式 SSE、数据查询 |
| 元数据库 | PostgreSQL | 存会话、语义层、审计、评测集；与只读 MySQL 分离 |
| 缓存/限流 | Redis 可选 | 单机可先不用，后续加 |
| SQL 解析 | sqlglot | AST 解析、语法校验、只读/多语句/DDL/DML 拦截 |
| MySQL 驱动 | SQLAlchemy + PyMySQL | 只读连接池，设置超时与行数上限 |
| LLM 接入 | 自研 LLM Gateway | 统一供应商、超时、重试、脱敏、审计 |
| 向量检索 | pgvector 可选 | 指标/同义词/示例问题相似检索 |
| 部署 | Docker Compose + Nginx | 内部单租户 |
| 监控 | 结构化日志 + Prometheus/Grafana 可选 | trace_id 贯穿 |
| 评测 | Python 离线 Harness | 100 条标注集，单问级判定 |

# 4. 核心模块设计

## 4.1 认证与会话

- 账号密码登录，密码 bcrypt/argon2 哈希。
- JWT 或服务端 Session；内部单租户，不做 SSO。
- 业务运营与管理层同数据同权限；一期不做行级权限。
- 会话表保留最近 10 轮完整消息，更早轮次生成摘要。
- 新话题识别：LLM 分类 + 规则（指标/维度/实体显著变化）判断；命中后返回 `new_topic` 事件，前端提示“检测到新话题，已新建会话，原会话保留”，并创建新会话，不静默清空。

## 4.2 对话编排 Conversation Orchestrator

职责：维护槽位状态、指代消解、追问决策、调用 NL2SQL、组织回复。

槽位建议：
- 指标 metric
- 时间范围 time_range
- 粒度 granularity
- 维度 dimension
- 筛选 filters
- 对比对象 compare
- 意图 intent：趋势/同环比/排名/对比/异常/归因

流程：
1. 接收用户问题。
2. 合并当前会话槽位与最近 10 轮上下文。
3. LLM 做意图识别与槽位抽取。
4. 判断是否明确：
   - 不明确且追问次数 <2：生成 1 个自然语言澄清问题，返回 `clarify`，不阻断；
   - 明确：进入 NL2SQL。
5. 查询成功后调用图表、异常、归因、解读服务。
6. 返回结构化消息；前端 SSE 流式展示状态。

追问规则：仅问题不明确时触发；一次 1 个；最多连续 2 次；用户不回答可继续问。

## 4.3 语义层与内置推断

一期无完整数据字典，采用“自动推断 + 后台轻量补充”：

1. 读取 MySQL `information_schema`：表、字段、类型、注释、索引。
2. 对表做小样本采样（脱敏后）和值分布统计。
3. LLM 生成候选：表业务含义、字段同义词、指标候选、维度候选、时间字段、口径说明、示例问题。
4. 写入 PostgreSQL 语义元数据表，标记 `auto_inferred`。
5. 管理后台可人工确认/修正指标口径、同义词、时间字段、可见字段、脱敏字段。
6. 检索时用 pgvector + 关键词混合召回，提升 NL2SQL 准确率。

**风险提示**：90% SQL 准确率强依赖语义层质量；建议一期保留轻量后台配置能力，即使默认自动推断。

## 4.4 NL2SQL 服务

输入：用户问题、槽位、会话摘要、召回的表/字段/指标/示例问题、SQL 方言。

输出：候选 SQL、使用的表字段、置信度、解释性元数据（不返回前端 SQL）。

Prompt 约束：
- 只生成单条 SELECT；
- 只使用白名单表和字段；
- 必须带时间/筛选条件；
- 自动加 `LIMIT 1001` 用于检测截断；
- 禁止注释、多语句、DDL/DML、系统表。

校验：
1. `sqlglot` 解析 AST，语法校验；
2. 校验表/字段存在且在语义层白名单；
3. 拦截多语句、DDL/DML、`information_schema`、文件读写、注释绕过；
4. 应用层追加/检查 `LIMIT`；
5. 通过后进入执行器。

## 4.5 SQL 执行与重试

- 只读账号连接池；设置 `max_execution_time=30000ms`；应用层超时 30s。
- 返回行数上限 1000；若命中 1001 行则截断并提示“结果过多，已展示前 1000 行”。
- 失败或空结果：
  - 将错误信息、原 SQL、schema 摘要、用户问题发给 LLM 修正 1 次；
  - 再校验、再执行；
  - 仍失败：返回“无法生成可靠查询，请补充指标/时间/维度或换个问法”；
  - 空结果重试后仍空：返回“未查询到数据，请确认筛选条件”。
- 不向用户展示 SQL、表名、字段名和错误堆栈。

审计建议：SQL 可加密存储并仅管理员可见，或存 SQL 哈希 + 脱敏摘要；具体按合规待定。

## 4.6 图表服务

自动选型规则引擎：
- 时间趋势 → 折线图；
- 分类对比/排名/TOP N → 柱状图；
- 时间 + 多系列构成 → 堆叠柱状图；
- 占比/构成 → 饼图。

一期只支持折线、柱状、堆叠柱、饼图；不可手动切换；排名用柱状图。图表数据由后端整形为 ECharts option，前端渲染。图表卡片包含标题、筛选摘要、图表、解读区、异常标记；分享按钮位置预留但隐藏。

成功口径：返回非空图表且无系统错误。

## 4.7 异常检测与归因

异常检测：
- 对时间序列结果计算同比/环比/滚动窗口偏差；
- 阈值后台可配；超阈值标记异常点；
- 返回异常点、方向、幅度，供图表标记和解读引用。

归因：
- 从语义层获取可用维度候选；
- 对异常或变化执行维度贡献拆解 SQL；
- 贡献度 = 维度值变化量 / 总变化量；
- 输出“主要贡献维度 + 数值”，不解释外部原因、不编造；
- 无显著维度时返回“未发现显著维度”。

## 4.8 数据解读

- 每个图表自动生成 3–5 条。
- 输入仅图表内聚合数据、筛选条件、异常/归因结果；不传明细。
- Prompt 要求：引用具体数值；不给行动建议；推测必须加“推测：”。
- 输出结构化 `insights[]`，前端逐条展示。

## 4.9 脱敏与 LLM Gateway

- 配置脱敏字段和规则：掩码、哈希、泛化、禁止发送。
- 发送 LLM 前对 schema 注释、样本值、用户问题、聚合结果做脱敏。
- LLM Gateway 统一处理：供应商路由、超时、重试、限流、日志、trace_id、成本统计。
- 只发送必要上下文；明细数据不发送；优先发送聚合结果。
- 公有云模型合规评审列为上线前置项。

## 4.10 管理后台

- 数据源：MySQL 连接、只读账号、表范围、字段可见性。
- 语义配置：指标、维度、时间字段、同义词、口径、示例问题、脱敏字段。
- 异常阈值配置。
- 审计日志检索：用户、时间、会话 ID、问题摘要、查询状态、错误码、耗时、是否追问、是否重试、是否异常/归因。
- 评测集管理：100 条标准问题、标注 SQL、运行评测。

## 4.11 二期预留

- 分享：`POST /api/share` 预留；仅内部登录、水印用户名+时间、有效期默认 7 天、按角色/部门权限、禁止 SQL/明细。
- 输入联想/猜你想问：`GET /api/suggestions` 预留，前端容器隐藏。
- 收藏/导出/移动端/表格明细二期。

# 7. 部署与运维

- Docker Compose：Nginx + FastAPI + PostgreSQL + Redis（可选）+ 前端静态资源。
- MySQL 只读账号独立配置，网络白名单。
- 环境变量管理 LLM Key、数据库连接、脱敏规则。
- 结构化日志 + trace_id；记录耗时、状态、错误码，不记录明文敏感数据。
- 备份：PostgreSQL 每日备份；审计日志保留期待定。
- 限流：登录接口、消息接口按用户限流。

# 8. 评测与可观测

**SQL 准确率评测：**
- 100 条标准问题，覆盖趋势、同环比、排名、对比、异常、归因。
- 单问级判定；自动重试后正确算对。
- 判定建议：优先比较执行结果集（列、行、数值容差），辅以 SQL AST 规范化对比。
- 目标 ≥90%；未达标时优先补语义层、示例问题和同义词。

**提问到图表成功率：**
- 主口径：返回非空图表且无系统错误。
- 埋点覆盖：提问、追问触发/回答、SQL 校验失败、执行失败/空结果、重试、图表类型、解读生成、异常标记、归因、新话题、会话新建。
- 是否排除“结果不对”样本待定。

**监控指标：**
- 请求量、P95 延迟、LLM 延迟、SQL 执行耗时、重试率、失败率、空结果率、图表成功率、追问率、新话题触发率、归因命中率、Token 成本。

# 9. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 无完整数据字典导致 90% 难达成 | 自动推断 + 后台轻量确认；用 100 条评测集迭代；必要时补语义层 |
| 自动归因维度不足 | 明确提示“未发现显著维度”；后台补维度元数据 |
| LLM 编造解读 | 只传图表聚合数据；Prompt 强制引用数值、推测标注；后置规则校验 |
| 脱敏不彻底 | 脱敏规则前置、字段级禁止发送、聚合优先、合规评审 |
| 新话题误判 | 提示并新开会话，不静默清空；保留原会话 |
| SQL 注入/越权 | AST 校验、白名单、只读账号、单语句、超时、行数限制 |
| 空结果重试改口径 | 重试仅修正语法/字段/条件表达，不擅自改指标口径；仍空给提示 |
