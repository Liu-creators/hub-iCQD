# DataAgent 功能设计文档

版本：V1.0｜日期：2026-10-22｜状态：拟建需求，非已实现功能清单

配套文档：[项目设计文档](项目设计文档.md)、[技术设计文档](技术设计文档.md)。本文定义用户能做什么、系统如何响应以及如何验收。

## 1. 功能范围与角色

MVP 支持内部用户基于单个启用的 SQLite 数据源开展只读问数与有限分析。每个任务只能使用一个数据源，数据源 ID 由管理员注册，用户输入不能直接指定任意数据库路径。

| 角色 | 允许操作 | 约束 |
| --- | --- | --- |
| 业务用户 | 提问、补充口径、追问、查看本人任务与结果、取消本人任务、清除本人会话 | 只能查询已授权数据源与表列 |
| 分析用户 | 业务用户能力，加上查看授权范围内 SQL 与执行参数 | 不能通过编辑 SQL 绕过执行策略；MVP 不开放直接 SQL 编辑入口 |
| 数据管理员 | 注册数据源、刷新结构、配置表列策略、指标词典与模型外发规则 | 配置写入应用管理库，不修改业务库 |
| 运维人员 | 查看脱敏阶段日志、耗时与错误、维护服务 | 不自动获得业务结果和原始问题读取权限 |

单组织部署也必须识别用户；MVP 可以采用管理员分发的独立用户令牌。后续接入组织登录体系时，保留相同的资源授权规则。

## 2. 典型用户流程

### 2.1 明确问题

1. 用户选定已授权数据源并提问。
2. 系统识别指标、维度、时间、筛选和输出数量；读取必要的授权结构。
3. 系统展示简短计划，例如“确认销售额口径，按国家汇总，再按金额降序取前十”。
4. 生成并检查查询，通过受控工具执行。
5. 核验结果的粒度、单位、时间和完整性。
6. 输出结论、关键数据、口径、证据和限制；允许继续追问。

### 2.2 需要澄清

用户问“最好的客户是谁？”如果词典没有默认排名指标，系统提出“按累计消费额还是订单数排名？”并进入 `awaiting_input`。用户补充后继续同一任务，不重复创建原任务，不重置预算。

允许把相关的两三个缺失项合并为一轮询问。最多两轮澄清仍不能形成可执行需求时，停止并说明缺少哪些条件。不能自行编造“利润”“活跃”等业务定义。

### 2.3 多轮追问

用户上一轮确认了“订单金额、2023 年、按国家分组”，下一轮说“只看加拿大”。系统保留指标和年份，更新国家筛选并告知继承条件。若用户要求“换成订单数”，只替换指标，清除与旧指标冲突的派生条件。

以上数据名称和年份仅用于说明交互；本目录未提供相应业务库或真实查询结果。

## 3. 功能需求

### F01 数据源注册与健康检查（MVP / P0）

**使用者**：数据管理员。

**输入**：数据源名称、服务端数据库路径、允许用户、表列策略、时区和可外发级别。

**规则**：路径必须由服务端配置并落在允许目录；文件存在才可注册。检查只读连接、结构读取与策略是否有效。空表属于合法结构；不因空表众数或样例为空而使整个数据源失效。

**输出**：数据源 ID、类型、状态、结构版本和最近检查时间。用户可见列表不暴露本机绝对路径、连接凭据或无权限的表名。

**验收**：不存在的路径被明确拒绝；只读账户可用；含空表的数据源可注册；无权限用户无法看到该数据源。

### F02 数据结构理解与按需检索（MVP / P0）

**输入**：数据源 ID、当前用户授权、用户问题。

**处理**：先获得授权表和字段摘要，再按相关性检索候选表，补齐必要的关联路径；仅在确有需要且策略允许时读取有限样例。未提供外键时可以引用管理员维护的关联规则，不能把名称相似视为已确认关联。

**输出**：候选表、字段类型、主外键、业务描述、结构版本，以及上下文是否被裁剪。

**规则**：相关表集是查询计划的一部分，权限集由服务端独立决定。扩大相关表集必须仍处于授权范围，并生成新查询检查结果。管理员可访问的结构不意味着普通用户或模型也能访问。

**验收**：选表提示只包含已授权元数据；大 Schema 超预算时按需检索，不直接截断成无法关联的上下文；结构改变后能失效刷新。

### F03 指标口径与时间处理（MVP / P0）

**输入**：自然语言、业务词典、会话中已确认事实。

**输出**：结构化需求：指标、聚合、维度、筛选、日期范围、排序、Top N、单位，以及未确定项。

**规则**：

- 业务词典定义指标公式、时间字段、币种或单位、去重键、适用表和有效版本。
- “销售额”不能在无依据时选择订单总额或明细金额；JOIN 后的重复计数必须核验。
- “去年”“最近一个月”等根据用户时区和请求时间解析，采用明确的起止日期，并向用户展示。
- 历史数据没有覆盖当前日期时，不悄悄将“去年”改为数据库最后一年；说明覆盖范围并询问是否改用数据最后一年。
- 多币种不能无汇率或明确口径直接相加；不清楚时澄清或分币种展示。
- 默认日期边界采用左闭右开区间，底层存储时区和业务日期字段含义由管理员配置。

**验收**：相同问题在相同词典、时间和会话状态下形成一致需求；缺少核心口径进入澄清，不能以模型自报置信度代替规则。

### F04 需求澄清与不可答识别（MVP / P0）

**触发**：指标、主体、日期或关联语义缺失会实质改变答案；请求超出数据覆盖范围；当前工具不能支持问题。

**输出**：简短问题、可选口径、缺失字段说明；状态为 `awaiting_input`。如果已有明确的禁止操作，例如要求删除数据，则直接失败并说明只读范围，不通过澄清反复尝试。

**规则**：已有明确且已告知的默认口径可直接使用；非关键展示偏好不阻断查询。最多两轮澄清；等待 30 分钟到期后进入 `timed_out`，重新分析需创建新任务。

**验收**：“利润”缺少成本数据时不能自行计算；明确任务不出现多余追问；用户补充只更新对应缺失项。

### F05 有限计划与动作选择（MVP / P0）

**输入**：结构化需求、授权结构、任务预算。

**输出**：可读计划摘要和结构化动作，动作限定为 `clarify`、`inspect_schema`、`query`、`verify`、`answer`、`stop`。

**规则**：

- 简单任务只查询一次；复杂任务按需要执行基准统计、分组对比和核验，默认最多三次正式数据查询。
- 模型提出动作后，由程序检查参数、权限和剩余预算。
- 相同失败原因与查询指纹重复出现时停止无效循环。
- 展示计划、进度和简短决策理由，不展示隐藏推理过程。
- 不能通过问题文本新增工具、调用 Shell 或修改预算。

**验收**：一条查询足够回答的问题不会无条件探索；需要补查时能说明补查目的；达到任何硬限制即停止后续调用。

### F06 SQL 生成与检查（MVP / P0）

**输入**：已确认需求、相关且授权的结构、方言和指标规则。

**输出**：一条参数化只读查询、绑定参数、引用表列、指标说明，以及受服务端管理的已验证查询 ID。

**规则**：解析完整语句列表，不能仅按前缀或分号判断。允许的 CTE 最终必须是只读查询；拒绝 DML、DDL、ATTACH、模型生成的 PRAGMA 和非白名单函数。处理别名、CTE、子查询和视图的实际依赖；无法证明合规时拒绝执行。

检查阶段不能实际运行原查询来“试错”。通过结构检查后，可在同一安全策略下执行受限的 `EXPLAIN QUERY PLAN` 进行数据库可编译性检查；它不是业务查询结果。

**验收**：拒绝 `WITH ... UPDATE`、多语句和未授权表列；`SELECT ';'` 这类字符串字面量不被误认成多语句；无表常量查询按产品策略允许。

### F07 查询执行与结果边界（MVP / P0）

**输入**：已验证查询 ID、任务身份、策略版本和绑定参数。

**输出**：实际执行 SQL、列定义、有限行数据、返回行数、`has_more`、截断原因、查询时间、耗时与证据 ID。

**规则**：

- 所有业务库访问采用只读连接与表列授权，包含 Schema 样例、计划检查、正式查询和核验补查。
- 默认最多向用户展示 50 行。对逻辑结果最多取 51 行以判断是否还有更多，只展示前 50 行。
- `returned_rows` 只表示展示行数；未经完整 COUNT 不能声明总行数。
- 用户要求 Top 10 时保留业务 LIMIT 10。10 行完整返回不属于系统截断；说明这是排名前十，不扩展为全量结论。
- 用户请求超过系统上限时说明仅展示部分；用户 SQL 逻辑上限、展示上限和模型上下文上限分别记录。
- 外层限行不能替代执行超时、CPU 与内存控制；长查询必须可中断。
- 不默认执行额外 COUNT；精确总数需要独立、受预算约束的查询。

**验收**：49、50、51 行分别判断正确；用户 LIMIT 和系统 LIMIT 语义清楚；查询超时后终止底层执行而非只让接口返回超时。

### F08 错误恢复与结果核验（MVP / P0）

**输入**：SQL 检查/执行反馈、结果对象、原需求和剩余预算。

**规则**：

| 情况 | 系统行为 |
| --- | --- |
| 表字段拼写、SQL 语法错误 | 最多两次 SQL 修复；每次重新走完整检查 |
| 结构版本变化 | 刷新授权结构后重验；仍受查询和工具预算约束 |
| 未授权访问或禁止语句 | 立即停止，不把拒绝信息当作绕过策略的提示 |
| 短暂模型网络故障 | 可进行一次传输重试，计入模型请求预算 |
| 查询执行超时或资源超限 | 中断本次任务；MVP 不自动扩大资源或重跑同一查询 |
| 无结果 | 说明当前条件无匹配记录；不能自动放宽筛选后冒充原问题答案 |
| 空值、零值 | 分开处理；未知值不解释为零 |
| 结果与口径不一致 | 在预算内修正或补查；无法核验时标为受限结果 |
| 总结阶段失败 | 保存表格、SQL 与口径，用确定性模板输出，标记降级 |

**核验项**：日期覆盖、指标公式、JOIN 基数、去重、维度粒度、币种与单位、排序和 Top N、空值、业务 LIMIT 与系统截断。部分核验可使用已有结构和结果，无需新增查询。

**验收**：能执行但口径错误的查询不能直接算作正确答案；执行错误也纳入分类恢复，不局限于校验错误；修复不重置预算。

### F09 证据化答复（MVP / P0）

**输出结构**：

1. 直接结论：根据实际结果回答用户问题。
2. 关键数据：表格、关键数值和单位。
3. 统计口径：时间、指标、维度、筛选、去重方式和继承条件。
4. 证据：数据源、实际执行 SQL、脱敏参数、查询时间与证据 ID。
5. 限制：无结果、部分返回、数据覆盖、无法核验项和降级说明。

**规则**：数值必须对应结果单元格或明确的确定性派生计算。数据库字符串只是数据，不能改变系统规则；总结输入经过策略过滤。外发禁用或不允许发送明细时，以本地模板生成答案，不能为了总结把原始数据发送给模型。

“实际执行 SQL”包括系统限行改写；同时保留原始逻辑 SQL 便于理解。结果已被截断时，不根据展示的部分行推断全量总额或全局排名。因果问题只能在数据支持范围内给出变化线索。

**验收**：答案数字可追溯；没有执行成功的查询不能出现在“证据已执行”列表；空结果不产生虚构分析。

### F10 会话记忆与追问（MVP / P0）

**保存内容**：已确认指标、时间范围、维度、筛选、任务和证据引用、澄清回答以及词典版本。

**规则**：会话绑定用户和数据源；切换数据源时开启新会话或明确清空旧数据事实。每次继续任务重新检查身份与权限。历史结果不能视为实时数据；用户要求最新结果时重新查询，并显示新的查询时间。

会话只继承当前问题需要的结构化事实。用户可以纠正或清除这些事实。会话内容不是新的系统指令，也不能继承管理员权限。

**验收**：“只看某国家”正确继承指标；“换指标”清理冲突；其他用户无法访问或引用该会话和结果。

### F11 任务状态、进度与取消（MVP / P0）

**输入**：创建任务、读取状态、提交澄清、请求取消。

**输出**：任务 ID、状态、当前阶段、脱敏事件、预算消耗与最终结果。

**规则**：任务创建使用幂等键防止重复。取消后停止新增工具调用并中断活动查询；正在等待的模型返回被丢弃，不能写成成功。API 先接受取消请求，待执行器确认后再进入 `cancelled`。

服务重启后，MVP 不静默重复运行未完成的数据任务：原 `running` 任务标记失败并说明执行中断；用户可基于旧证据新建任务。已持久化的 `awaiting_input` 任务可以在有效期内继续。

**验收**：轮询不会重复执行任务；取消后没有新的查询；失败保留已经完成的证据与可理解原因。

### F12 安全、外发与审计（MVP / P0）

**管理员配置**：允许用户/角色、表列白名单、敏感字段、可用函数、允许进入模型的内容类型、保留期限与资源上限。

**规则**：身份与资源授权由程序执行；提示词不能承担授权。Schema、样例、正式结果、日志、错误和总结均应用同一数据策略。数据库中的提示注入文本按普通字段值处理，不能触发工具操作。

业务数据只读不影响应用保存会话、任务和审计；两者存储隔离。日志默认不记录原始行数据、密钥或完整异常堆栈给用户。结果原值的可见权限与模型外发权限分别判断。

**验收**：新增敏感字段默认不可用；撤销权限后旧结果不可继续读取；关闭模型外发时仍可本地模板答复。

### F13 反馈、评测与运行信息（MVP / P0；扩展 P1）

**MVP**：运行者可以看到阶段耗时、模型请求数、工具次数、查询次数、修复次数和错误分类；有固定输入和期望结果的离线评测集，以及需要真实模型的独立端到端评测。

**P1**：用户标记“口径错误”“查询错误”“解释错误”；反馈进入人工复核样例，不自动改写全局指标或权限。

**验收**：正确率按问题答案和口径计算；SQL 可执行率、修复率与答案正确率分别统计。

## 4. 统一任务状态

状态与工作阶段分开。`running` 时的阶段可以是理解、检索、规划、检查、查询、核验或总结。

| 状态 | 含义 | 允许后续 |
| --- | --- | --- |
| `accepted` | 请求已校验并持久化，尚未开始 | running / cancelled / timed_out / failed |
| `running` | 正在执行任务 | awaiting_input / succeeded / succeeded_with_warnings / failed / cancelled / timed_out |
| `awaiting_input` | 缺少用户补充，等待期间不运行工具 | running / cancelled / timed_out |
| `succeeded` | 需求已回答，证据完整 | 终态 |
| `succeeded_with_warnings` | 已有有效查询，但只能给受限结果或模板答复 | 终态 |
| `failed` | 无法完成、越权、策略拒绝或执行中断 | 终态 |
| `cancelled` | 已确认终止，无后续执行 | 终态 |
| `timed_out` | 活动时间、查询时间或等待输入期限耗尽 | 终态 |

预算耗尽时：已有合法结果则可用模板形成 `succeeded_with_warnings`；没有合法结果则 `failed/BUDGET_EXCEEDED`。活动截止时间超限统一为 `timed_out`。终态不可被迟到的模型结果覆盖，继续提问创建新任务。

## 5. 默认资源限制

这些是拟定配置值，应在性能测试后调整。用户和模型不得在单次任务中提高它们。

| 限制 | MVP 默认值 | 计数口径 |
| --- | --- | --- |
| 正式查询 | 3 次/任务 | 包括失败查询与核验补查，不含 EXPLAIN；EXPLAIN 仍消耗工具次数和时间 |
| SQL 修复 | 2 次/任务 | 初次生成之外，所有 SQL 修正累计 |
| 模型请求 | 8 次/任务 | 包括结构化格式修复与传输重试；关闭隐藏自动重试 |
| 工具调用 | 12 次/任务 | 含失败调用；编排器先占用预算再执行 |
| 澄清 | 2 轮/任务 | 等待不消耗活动时间，但计入等待期限 |
| 单次 SQL 时间 | 5 秒 | 由可中断执行器负责，含取数 |
| 单次模型时间 | 15 秒 | 不超过任务剩余时间；外层任务调度也控制期限 |
| 单任务活动时间 | 60 秒 | 不包含等待用户输入；每次恢复累计 |
| 等待输入 | 30 分钟/轮 | 过期不自动恢复 |
| 展示结果 | 50 行 | 内部最多取 51 行用于判定是否更多，另设字节上限 |
| 问题长度 | 2,000 字符 | 超出则请求精简 |

上下文和 token 上限由实际模型容量与服务限制配置，拟定输入预算 12,000 token、单次输出 2,000 token、单任务总消耗 24,000 token；精确计算不可用时使用保守估算并记录误差，不能声称成本精确。

## 6. 结果展示与交互要求

MVP 的 CLI/API 必须表达数据源、计划摘要、阶段、结果、证据和限制。P1 Web 界面可采用会话列表、问答区、数据表格和证据抽屉；不能把建设 Web 界面当作实现 Agent 闭环的前置条件。

进度例如：“读取授权结构”“正在检查查询”“查询完成，正在核验”；未知总步骤时不展示虚假的完成百分比。默认隐藏后台堆栈和服务器路径。

显示查询时间与数据时间覆盖范围时必须区分：查询刚执行不代表数据刚更新。未获知数据更新时间时明确写“数据更新时间未知”。

P1 导出只能使用当前仍有权限的完整结果或重新受控查询；必须标注导出范围和截断情况，不能把 50 行预览命名为“全量数据”。

## 8. 可交付完成定义

一个功能必须同时具备正常流程、失败流程、权限和预算处理、结构化输出以及对应验收结果，才算完成。仅有提示词、工具名称或界面按钮不能算功能已实现。

MVP 交付时应提供实际数据源快照说明、40 条基础查询与10 条澄清样例的结果报告、安全与恢复用例报告、运行说明和配置模板。本文的示例与指标应由这些实际报告验证。
