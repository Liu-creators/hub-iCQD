1、 langchain 工具调用 和 llm function call 有什么区别？

LangChain工具调用是基于LLM Function Call的上层封装，不是替代关系。

详细对比:
| 维度 |	LLM Function Call（原生） | LangChain 工具调用 |
| :---: | :---: | :---: |
|抽象层级|	底层API调用	|高层框架封装|
|定义方式|	JSON Schema格式|	@tool装饰器或Pydantic类|
|调用流程|	手动解析、执行、管理消息|	自动处理（Agent）或半自动|
|消息管理|	手动维护messages列表|	自动管理（BaseMessage）|
|错误处理|	需手动try-catch|	内置错误处理机制|
|流式支持|	手动拼接tool_calls|	自动处理tool_call_chunks|
|多工具编排|	手动编写循环逻辑|	Agent自动决策（ReAct等）|
|依赖|	    仅需SDK|	需安装langchain生态|
|灵活性|	⭐⭐⭐⭐⭐ 完全控制|	⭐⭐⭐ 框架约束|
|开发效率|	⭐⭐ 代码量大|	⭐⭐⭐⭐⭐ 快速开发|

2、 langchain 工具调用 的 速度是受到什么影响？

总耗时 = 网络延迟 + 模型推理时间 + 工具执行时间 + 框架开销

主要因素（影响程度由大到小）：模型推理，网络延迟，调用次数，工具执行，框架开销

优化方向：

使用更小的模型，减少不必要上下文，使用缓存；

选择国内服务商，使用http/2复用，批量处理请求；

减少调用次数（合并多个查询，使用并行工具调用）；

工具函数保持轻量，使用异步执行，缓存工具结果；

避免过度复杂的工具schema，使用invoke而非stream，关闭不必要的日志。
