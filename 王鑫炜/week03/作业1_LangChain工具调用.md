# Week03 作业1：LangChain 工具调用

## 1. LangChain 工具调用和 LLM Function Call 有什么区别？

LLM Function Call 是模型厂商提供的底层能力。开发者需要向模型提供函数名称、参数说明和 JSON Schema；模型根据用户问题返回要调用的函数及参数，但函数仍然需要由程序执行。

LangChain 工具调用是在 Function Call 基础上的进一步封装。它可以通过 `@tool` 快速定义工具，统一不同模型厂商的调用格式，并提供工具参数解析、消息管理和 Agent 自动调度等功能。

- **LLM Function Call**：底层调用协议，控制更直接，但需要手动处理的内容较多。
- **LangChain 工具调用**：对底层协议进行统一封装，开发更加方便，也更适合组合多个工具和构建 Agent。


## 2. LangChain 工具调用的速度受什么影响？

LangChain 工具调用的速度主要受以下因素影响：

1. **大模型响应速度**：模型大小、服务端负载和生成内容长度都会影响响应时间。
2. **大模型调用次数**：工具调用通常至少请求模型两次，一次生成工具参数，一次根据工具结果生成最终回答。
3. **工具执行速度**：查询数据库、访问第三方接口或处理文件都可能增加耗时。
4. **网络延迟**：访问远程模型和外部工具时，网络质量会直接影响速度。
5. **工具数量和提示词长度**：工具越多、描述越复杂，模型需要处理的上下文越长。
6. **执行方式**：多个工具串行执行通常比并行执行更慢。

因此，LangChain 框架本身的额外耗时通常较小，主要耗时来自大模型请求、网络通信和工具执行过程。
