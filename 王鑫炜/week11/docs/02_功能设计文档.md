# Chinook ChatBI 功能设计

本设计定义单次自然语言问答的输入、处理状态、输出和异常行为。当前通过命令行调用；Web 查询台和会话管理属于后续产品范围。

## 问答流程

1. 输入 1～4000 字符的问题；校验数据库路径和运行参数。
2. 解析数据库元数据，提供表描述与可读字段供模型选择。
3. 指标、时间或需求不明确时返回具体追问，结束本次执行。
4. 校验所选表并补齐外键路径，将相应表结构交给 SQL 生成阶段。
5. 编译 SQL；若遇权限错误直接拒绝，普通 SQL 错误进入有限改写。
6. 只读执行。运行错误同样可以改写，每次改写后重新编译并重新施加权限。
7. 用真实结果生成中文回答，保留 SQL、数据、解释和阶段记录。

## 功能定义

| 编号 | 功能 | 输入与输出 | 验收例子 |
| --- | --- | --- | --- |
| F01 | 数据库解析 | 文件路径 → 表、列、主外键、行数、日期范围 | 识别 11 张业务表和发票日期范围 |
| F02 | 语义选表 | 问题与目录 → 表清单、依据或澄清问题 | 国家销售额选择 invoices |
| F03 | 连接表补全 | 表清单与外键图 → 可连接的表集合 | artists 和 invoice_items 补入 albums、tracks |
| F04 | SQL 生成 | 问题、所选 schema、函数白名单 → SQL 与口径解释 | 流派收入使用明细成交价乘数量 |
| F05 | SQL 校验 | SQL 与可访问表 → 查询计划或报错 | 不存在的 Amount 字段产生真实错误 |
| F06 | SQL 改写 | 问题、原 SQL、报错、schema → 修正 SQL | Amount 改为 Total；默认最多两次 |
| F07 | 受限执行 | SQL → 列名、数据、行数与截断标志 | 默认最多输出 50 行 |
| F08 | 结果总结 | 真实结果和口径 → 中文回答 | 无匹配记录时明确空集，不编造原因 |
| F09 | 过程输出 | 各阶段状态 → JSON trace | 能找到改写前后的 SQL 和真实报错 |
| F10 | 离线演示 | 预设 ID → 固定模型响应加真实数据库执行 | 任意新问题不能冒充已获理解 |

## 状态与失败规则

`ok` 表示查询和总结完成；`needs_clarification` 表示问题仍缺关键条件；`partial` 表示查询完成但模型总结失败；`blocked` 表示权限拒绝；`error` 表示其他失败。

普通 SQL 校验或运行错误共享最多两次改写预算，不是每一阶段各允许两次。每个模型阶段的格式错误最多再纠正一次。HTTP 429 和指定临时服务错误最多请求三次；认证错误不重试。权限错误不进入 SQL 改写。

表名不存在或所选表之间无外键路径时停止，并说明原因。SQL 可访问的表限定为已选集合及外键补全表，不能在改写中擅自扩展。

## 输入与结果约束

问题长度上限为 4000 字符，SQL 上限为 20000 字符。最大输出行数可设 1～1000，默认 50；结果数据值文本合计超过 64000 UTF-8 字节时停止并要求缩小范围。不是对整个 JSON 文件大小的限制。

输出 `truncated=true` 表示仍有更多结果，显示的只是预览。恰好返回上限行数且没有更多结果时，不标记截断。空数组表示没有匹配记录；聚合结果中的 `NULL` 保留，不自动转为零。

全局禁止读取邮箱、电话、传真、地址、生日和邮编相关列。权限针对 SQL 实际读取列生效，也包含子查询；不能只靠提示词禁止访问。当前不是基于用户身份的完整授权系统。

## 调用示例

```bash
python3 main.py '2013 年每月的发票销售额分别是多少？'
python3 main.py --demo bridge_join
python3 main.py --demo country_sales --max-rows 2
```

`--output` 保存与终端相同的 JSON。失败状态返回非零退出码；澄清状态正常返回，由使用者补全问题后发起新的单次查询。输出文件可能包含业务结果，默认不自动保存。

## 后续界面

Web 查询台拟提供问题输入、当前过滤条件、澄清提示、结果表、图表、SQL 展开区和错误详情。图表必须基于返回结果生成，截断时显示预览标识。多轮追问需要保存显式过滤条件，避免把模型历史文本当成已验证数据。上述界面与会话功能未包含在当前 CLI 代码中。
