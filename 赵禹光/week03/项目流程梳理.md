# 意图分类项目 — 源文件作用 & 请求处理流程

---

## 一、源文件作用

| 文件 | 作用 |
|------|------|
| `main.py` | **入口文件**。用 FastAPI 创建 4 个接口，每个接口的处理逻辑一致：记录开始时间 → 构造响应体 → 调用模型函数 → 捕获异常 → 计算耗时 → 返回结果 |
| `data_schema.py` | **数据格式定义**。用 Pydantic 定义请求体（`TextClassifyRequest`）和响应体（`TextClassifyResponse`），FastAPI 自动完成参数校验和序列化 |
| `config.py` | **配置中心**。存放：正则规则字典、12 个分类标签、TF-IDF/BERT 模型文件路径、LLM API 地址/密钥/模型名 |
| `logger.py` | **日志模块**。配置 logging，同时输出到控制台和 `app.log` 文件 |
| `model/regex_rule.py` | **正则规则分类器**。启动时将 `config.py` 中的关键词预编译为正则表达式，请求到来后直接 `findall` 匹配，未命中则返回 `Other` |
| `model/tfidf_ml.py` | **TF-IDF + 传统 ML 分类器**。启动时加载训练好的 `.pkl`（TF-IDF 矢量器 + 分类模型）。请求到来后：jieba 分词 → 去停用词 → TF-IDF 向量化 → 模型预测 → 返回类别 |
| `model/bert.py` | **BERT 深度学习分类器**。启动时加载 `bert-base-chinese` 预训练权重 + 微调后的分类头。请求到来后：tokenize（max_length=30）→ DataLoader 分批 → GPU/CPU 推理 → argmax 取最大概率类别 |
| `model/prompt.py` | **LLM 大模型分类器（通义千问）**。不依赖训练，通过 Few-shot 提示词实现。请求到来后：TF-IDF 检索训练集中最相似的 10 条样本 → 拼入提示词模板 → 调用通义千问 API → 返回模型输出的类别 |
| `assets/dataset/dataset.csv` | **训练数据集**。两列：文本 + 标签。LLM 模式使用该数据做 Few-shot 相似检索 |
| `training_code/train_tfidf.py` | **TF-IDF 模型训练脚本**。训练完成后输出 `assets/weights/tfidf_ml.pkl` |
| `training_code/train_bert.py` | **BERT 模型训练/微调脚本**。微调 bert-base-chinese，输出 `assets/weights/bert.pt` |
| `test/data.json` | **压测请求体**，配合 ApacheBench（ab）命令进行批量压力测试 |
| `fastapi_demp.py` | **FastAPI 教学示例**（与项目功能无关），演示基础的 GET 路由写法 |

## 二、请求处理流程

```
客户端发送 POST 请求
   │
   ▼
┌──────────────────────────────────────────────────┐
│  FastAPI 接收请求                                  │
│  - 根据 URL 后缀（regex/tfidf/bert/gpt）路由到对应函数│
│  - 自动调用 data_schema.py 中的 Pydantic 模型校验参数 │
│  - 校验失败直接返回 422                              │
└──────────┬───────────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────────┐
│  进入接口函数（main.py 中 4 个函数之一）              │
│  ① 记录开始时间 start_time = time.time()           │
│  ② 构造空的响应对象 TextClassifyResponse（默认值）    │
│  ③ logger.info 记录请求日志                        │
└──────────┬───────────────────────────────────────┘
           │
           ▼
      路由分发（四选一）
           │
    ┌──────┼────────┬──────────┐
    ▼      ▼        ▼          ▼
  regex   tfidf    bert       gpt
    │      │        │          │
    │      │        │          │
    ▼      ▼        ▼          ▼
┌────────┐ ┌──────┐ ┌──────┐ ┌──────────────────┐
│正则匹配 │ │jieba │ │BERT  │ │ TF-IDF 检索最相似 │
│关键词   │ │分词  │ │推理  │ │ 10 条 → 拼入提示词 │
│findall │ │→TFIDF│ │      │ │ → 调通义千问 API  │
│        │ │→预测 │ │      │ │                  │
└───┬────┘ └──┬───┘ └──┬───┘ └────────┬─────────┘
    │         │        │              │
    └─────────┴────────┴──────────────┘
                    │
                    ▼
┌──────────────────────────────────────────────────┐
│  返回接口函数                                     │
│  ④ 成功 → 填充 classify_result + error_msg = "ok" │
│  ⑤ 失败 → classify_result = "" + 填充异常堆栈信息   │
│  ⑥ 计算耗时 classify_time = round(time.time()     │
│                              - start_time, 3)     │
└──────────┬───────────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────────┐
│  FastAPI 将 TextClassifyResponse 序列化为 JSON     │
│  返回给客户端                                     │
└──────────────────────────────────────────────────┘
```

## 三、四种方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| regex | 关键词匹配 | 极快、零训练 | 泛化能力差，换个说法就失效 |
| tfidf | 词频统计 + 传统 ML 模型 | 速度快、有一定泛化能力 | 不理解语义，无法处理同义词 |
| bert | 预训练语言模型微调 | 理解上下文，准确率最高 | 推理慢，需要 GPU |
| gpt | 大模型 Few-shot | 零训练、灵活度高 | 调用 API 有延迟，有费用 |
